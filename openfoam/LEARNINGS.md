# OpenFOAM case-preparation learnings

- Export the three Inventor surface-body profiles independently in canonical order: `master.obj`, `mrf.obj`, then `master_1.obj`.
- Normalize only `master.obj`; this keeps snappyHexMesh limited to the physical inlet, heat-source, outlet, blade-cavity wall, and wall patches.
- Keep the closed `mrf.obj` and `master_1.obj` byte-preserving, staged as `mrf-zone.obj` and `aluminum-zone.obj` exclusively for `createZones`.
- `Allclean` retains profile inputs and staged helpers so a cleaned case remains runnable without a new CAD export.
- `verify_mesh_contract.py --check-mesh` now permits isolated concavity failures as warnings (emits `warning: checkMesh reported concavity-only failures` to stderr) while rejecting every other failure signature — mixed or non-concavity failures remain non-zero. Regression tests cover: concavity-only allowed, concavity+another failed check rejected, non-concavity failure rejected, mesh-OK passes.
- Confirmed master OBJ material RGB `(255,0,255)` maps exactly to `patch_blade`; it remains a master-only snappy wall patch with the standard level `(1 1)` refinement, reserved for later `MRFnoSlip` treatment.
- Keep ParaView discovery artifacts in source templates: `constant/regionProperties` declares `fluid` and `aluminum`, while the empty root `hs5-cht.foam` marker is stable across fresh renders. The steady `foamMultiRun` control template resumes from `latestTime` with bounded pseudo-time (`endTime 40`, `deltaT 1`) and ASCII output.

## Two-stage flow-to-thermal automation

The personal-project workflow runs flow then thermal without prompting.

**Official case path**: `~/a5100/hs5/openfoam/cases/hs5-cfd-current`. All tooling targets this single shared case; no ad-hoc remote paths.

**Local command**:
```
python tools/run_two_stage_cfd.py --case openfoam/cases/hs5-cfd-current
```

**Remote command** (inside the official remote case, after sourcing OpenFOAM v14):
```
bash run-two-stage.sh
```

The shell entrypoint is rendered from `openfoam/templates/run-two-stage.sh.tmpl` and delegates to the Python runner.

**`--fresh` flag**: removes only the latest generated numeric time directory (e.g. `200/`) before flow starts. It never touches the protected `0/`, `constant/fluid/`, or `constant/aluminum/` directories. Without `--fresh`, any existing time directories are left in place and the flow solver resumes.

**`--mesh` flag**: runs the full rendered `bash Allrun` mesh preflight (blockMesh, snappyHexMesh, createZones, splitMeshRegions, checkMesh gates) before the flow stage. Without `--mesh`, meshing is skipped and the runner assumes the case is already meshed.

**Stage order**: flow (`bash Allrun.flow`) then thermal (`foamMultiRun`). If flow fails or does not converge, thermal never starts and the runner exits non-zero.

**Convergence rules**:
- Flow stage: solver must print a convergence marker (e.g. `PIMPLE: converged`) with all four residuals (`p`, `U`, `k`, `omega`) present. Reaching `endTime` alone, even with low residuals, is **not** convergence.
- Thermal stage: solver must print a convergence marker with `h <= 1e-5` and `e <= 1e-6`. Hitting `endTime` alone is non-converged. This applies regardless of `endTime` cap; the cap produces a non-converged result.

**`result.json` keys** (written to `<case>/result.json`):

| Key | Type | Meaning |
|---|---|---|
| `flowConverged` | bool | flow stage met residual thresholds |
| `thermalConverged` | bool | thermal stage met `h` and `e` thresholds |
| `fluidTmaxK` | float or null | max internal fluid temperature in K |
| `solidTmaxK` | float or null | max internal aluminum temperature in K |
| `pressureDropPa` | float or null | inlet minus outlet pressure in Pa |
| `massFlowKgPerS` | float or null | magnitude of inlet mass flow in kg/s |
| `status` | string | `"success"` when both stages converge and all metrics are present; `"non_converged"` otherwise |

Missing or unreadable fields produce `null` metrics and a `non_converged` status.

**Protected inputs**: `0/` (initial/boundary conditions), `constant/fluid/` (fluid region properties and MRF), and `constant/aluminum/` (solid region properties) are never deleted or regenerated by the two-stage runner. Only generated numeric time directories may be removed.
